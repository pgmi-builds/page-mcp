## 2. 差点写出假报告：陈旧标签页

第一轮我复验 `05`，得出的是：

```
badge: (空)
dev_click {ref:"e1", bogus:1}  -> "Clicked e1 …"        # 没拒绝
dev_wait  {code:"nope…"}      -> 只有 timeout，无 THREW  # 没修
```

三条修复看起来全部没生效——足以写出一份「`05` 报告是错的」的复验。

实际原因：

| 事实 | 时间 |
|---|---|
| 那个 Chrome 启动 | **20:44:33** |
| 修复构建完成 | 21:14:59 |
| 修复件部署到 `view-dir` | **21:15:03** |

浏览器比部署早了 30 分钟。demo 投递是 `no-store`，**但一个已经打开的标签页不会因为服务器换了文件就换掉内存里的脚本**——它要 reload。我测的是旧 bundle。

强制 reload 后，同一份脚本、同一批断言，`05` 全部通过（§1）。

**教训（已进 06 §6 的同类）：核对「服务器上的文件」不等于核对「页面正在跑的代码」。** 两者的差集恰好等于「所有在部署之前打开的标签页」。复验任何前端改动前先 reload，并核对被测页面实际加载的那份构建。

> 顺带：这条也解释了为什么 `06` 的 `Page.captureScreenshot` 字节数和我不同（4770 vs 4481）——不同 viewport（他们 800×600，我 780×437）和不同页面状态，PNG 压缩后自然不同。**尺寸（130×33）才是可断言的部分**，字节数不是。

## 3. 06 的两处更正

### 3.1 `toDataURL` 的字节数对不上，但结论成立

| | 06 | 本次 |
|---|---|---|
| 帧外 `toDataURL` 长度 | 944 710 字符 | **11 274 字符** |
| 解码后非黑像素 | 全黑 | **全黑（0 / 4096）** |
| 是否合法 PNG | 是 | 是 |

**定性结论完全复现**，而且这是本轮最值得记的一条：帧外 `toDataURL()` 会**成功返回一个合法 PNG**，内容是黑的。agent 会把它当证据。这比抛异常危险得多。

但 **944 710 字符与「内容全黑」在物理上不相容**：全黑图几乎不压缩成本，780×437 也就 ~11 KB；要压到 700 KB，图里必须有大量高频内容。合理解释是那个数字来自另一次实验（例如 `preserveDrawingBuffer:true` 的合成 canvas，它确实有内容），被并到一行里了。**结论保留，数字标注为未复现。**

### 3.2 hit-test 误报的成因写错了

`06` §4.1 说误报原因是「disabled 的表单控件在 Chrome 里不参与命中测试」。实测这一页：

```
rect {x:538.59, y:378, w:130.34, h:33} | disabled: true | pointer-events: none
elementFromPoint      -> DIV.actions          # 父节点，不是按钮
elementsFromPoint     -> DIV.actions -> CANVAS -> DIV#scene -> BODY -> HTML
```

现象**逐字复现**（`elementFromPoint` 返回父节点 `DIV.actions`）。但 `computed pointer-events` 是 **`none`**，来源是应用自己的 CSS —— `demo/index.html:59`：

```css
.actions button:disabled{opacity:.28;pointer-events:none}
```

所以在这一页上，直接成因是**应用给 disabled 按钮关了命中测试**，而不是浏览器的 disabled 语义。差别不是学究：如果照 `06` 的归因去实现，遇到「disabled 但没关 pointer-events」的控件时会漏判；`06` 自己推导出的规则（用 `elementsFromPoint` 逐层、跳过 `pointer-events:none`、覆盖者是祖先则不算、自身不可命中记 `hitTestable:false`）**是对的，照做即可**——只是理由要换成「先看 computed style，再看 disabled」。
